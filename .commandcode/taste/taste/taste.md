# Taste
- The notebook metaphor applies to the inside pages only; entry/auth screens (login, register) should read as the *outside cover* of the book — pandan-green cloth, spine down the left, handwritten app title, form on a paper label pasted to the cover — not as a ruled notebook page. Confidence: 0.7
- Auth covers should carry the brand at the top: a mark/seal plus wordmark above the label. When the user sees empty space at the top of an auth screen they call it out ("nampak kosong") and want it filled with brand identity, not left blank or filled with a new animation. Confidence: 0.55
- Brand badges/logos on the auth cover must contrast with their container — a white mark inside a white circle ("logo putih, background circle avatar pun putih?") reads as invisible and gets flagged; prefer the full app icon (colored) with a paper rim over a single-color mark on a light disc. Confidence: 0.55
- Always build UI from the existing "notebook" design system rather than ad-hoc styling: use the Notebook theme extension (`Notebook.of(context)`), the core widgets `NotebookPage`/`NotebookRow`/`NotebookTitle`/`NotebookHeading`/`PinMark`, `ActionDock` for page actions, and `showNotebookSheet`/`showNotebookDialog` (tone info/confirm/danger). The Caveat font is reserved for page titles and user notes only. Confidence: 0.85
- For visual/design work, do deep research first — search the web for real-world reference photos (the actual physical object) and check the project's own brand/site for its visual language — before writing the implementation. A first pass built from general ideas gets rejected as "tak nice, tak sama" for not matching the real thing. Confidence: 0.7
- Navigation/motion should extend the book metaphor as a physically faithful page turn — flipping a paper page forward and back (he explicitly rejected swipe/sliding-sheet motion and fast, clunky timing), with a distinct reverse variant for back navigation rather than the same animation both ways. Build such effects once as a reusable theme-registered `PageTransitionsBuilder` shared by every route — not re-implemented per page. Confidence: 0.6
- Inline navigation links (e.g. "Daftar akaun" under the login label) should be plain text driven by a gesture/tap target with a comfortable hit area and subtle press feedback — not a Material `TextButton`, whose built-in padding, ripple and typography make the text look worse ("guna gesture, tak perlu guna text button"). Confidence: 0.6
- A link's arrow mirrors where it takes you: return/back links (e.g. "Log masuk" on register, "Ke log masuk" on forgot) get a left-pointing arrow placed *before* the label, while forward links keep the arrow after the text pointing right — he explicitly asked for "letak kiri dan guna left arrow". Confidence: 0.5
- When he says a page is broken ("rosak"), he usually means how it *looks*, not how it behaves — render the screen (golden/screenshot preview at a phone size) and look at it before changing navigation or logic; guessing at behaviour earns "kau tak faham eh". Confidence: 0.55
- Navigation must clear input focus: after pushing/popping routes, text fields should be unfocused so a previously focused field (e.g. email on login → register → back) doesn't regain focus when the page is restored. Confidence: 0.55
- Decorative background layers (cover base colour, texture, spine, page edge) must stay full-screen and fixed when the soft keyboard opens — only the form/content area may resize and scroll. A background that shrinks with the keyboard gets reported as a bug ("kenapa background bergerak kalau keyboard open?"). Confidence: 0.5
- Communicates in casual Bahasa Melayu ("aku/kau" register) and expects the same register back in replies and summaries. Confidence: 0.55
- All user-facing copy must go through l10n ARB files (Bahasa Melayu as default plus English) — never hardcode strings in widgets. Confidence: 0.85
